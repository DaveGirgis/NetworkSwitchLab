# Command Reference

## Standard ACL Commands

| Command | Purpose |
|---------|---------|
| `access-list [1-99] permit [address] [wildcard]` | Add a permit rule to a standard numbered ACL |
| `access-list [1-99] deny [address] [wildcard]` | Add a deny rule to a standard numbered ACL |
| `ip access-group [number] in\|out` | Apply a numbered ACL to an interface or SVI |
| `access-class [number] in\|out` | Apply a numbered ACL to VTY lines |
| `show ip access-lists [number]` | Display ACL rules and match counts |
| `no access-list [number]` | Remove an entire numbered ACL |

## Extended and Named ACL Commands

| Command | Purpose |
|---------|---------|
| `ip access-list extended [name]` | Enter named extended ACL configuration mode |
| `deny [protocol] [src] [dst] [options]` | Add a deny rule in named ACL mode |
| `permit [protocol] [src] [dst] [options]` | Add a permit rule in named ACL mode |
| `show ip access-lists [name]` | Display named ACL rules and match counts |
| `no ip access-list extended [name]` | Remove an entire named extended ACL |

**Common protocol keywords:** `ip` (all IP), `tcp`, `udp`, `icmp`

**Common ICMP type keywords:** `echo` (type 8 — ping request), `echo-reply` (type 0 — ping reply), `unreachable` (type 3)

**Source/destination syntax:**

| Syntax | Matches |
|--------|---------|
| `host 10.0.0.1` | Exactly 10.0.0.1 (equivalent to wildcard `0.0.0.0`) |
| `10.0.0.0 0.0.0.255` | Any address in 10.0.0.0/24 |
| `any` | All addresses (equivalent to `0.0.0.0 255.255.255.255`) |

## NAT Commands

| Command | Purpose |
|---------|---------|
| `ip nat inside` | Mark an interface as the inside (private) NAT boundary |
| `ip nat outside` | Mark an interface as the outside (public) NAT boundary |
| `ip nat inside source list [acl] interface [intf] overload` | Configure PAT — translate matching inside addresses to the specified outside interface address |
| `show ip nat translations` | Display active NAT translation entries |
| `show ip nat statistics` | Show translation counts, inside/outside interfaces, and miss statistics |
| `clear ip nat translation *` | Remove all dynamic NAT translations — useful when changing ACL membership |
| `debug ip nat` | Real-time NAT event output (use `no debug all` to stop) |

## General Verification Commands

| Command | Purpose |
|---------|---------|
| `show ip interface brief` | Interface status and IP address summary |
| `show running-config \| section access-list` | Show all numbered ACL entries |
| `show running-config \| section ip access-list` | Show all named ACL entries |
| `show running-config \| section ip nat` | Show NAT configuration |
| `show running-config \| section line vty` | Show VTY configuration including access-class |

## Discussion & Wrap-Up

**1. ACL rule processing — why order matters**

IOS evaluates ACL rules top to bottom and stops at the first match. If you have `deny host 10.0.0.1` followed by `permit any`, host `10.0.0.1` is denied and never reaches the permit. If those lines are reversed, `10.0.0.1` is permitted by the `permit any` before the deny is ever evaluated. When editing numbered ACLs, the entire ACL must be deleted and re-created in the correct order. Named ACLs allow individual lines to be deleted by sequence number, which is far more practical in production.

**2. Standard vs extended ACL placement**

Standard ACLs match only the source. If you place a standard ACL close to the source, it may block traffic to destinations you intended to allow. Placing it close to the destination limits the blast radius. Extended ACLs match source, destination, and protocol — placing them close to the source drops unwanted traffic early, before it uses bandwidth traversing the network.

**3. NAT overload vs static NAT vs dynamic NAT pool**

| Type | How it works | Use case |
|------|-------------|----------|
| Static NAT | One fixed inside→outside mapping | Servers that must be reachable by a consistent public IP |
| Dynamic NAT pool | Inside addresses map to a pool of outside addresses (one-to-one, pool exhausted when all are in use) | Legacy environments with multiple public IPs |
| NAT overload (PAT) | Many inside addresses share one outside IP, distinguished by port | Virtually all modern CE router deployments — one public IP serves an entire LAN |

**4. Why pings sourced from the router bypass NAT**

When you ping from a router (not from a PC behind the router), the source address is the router's outgoing interface address — which is already a public address. NAT only applies to packets arriving on the inside interface destined for the outside. A ping generated by R1 itself is not an inside packet; it originates on the outside interface and is not subject to translation. This is why `ping 198.51.100.1` succeeds from R1 before NAT is configured, but the same ping from PC-A does not.
